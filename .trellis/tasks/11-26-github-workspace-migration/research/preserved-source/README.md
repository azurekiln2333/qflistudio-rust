# Preserved historical source and evidence

This directory rescues selected authored source, historical patches and useful
evidence from ignored working directories and unreachable Git blobs.
`manifest.json` records original paths/object IDs, raw SHA-256 hashes, byte
counts, duplicate comparisons, dispositions and portable destinations.

## Not a product implementation or executable workflow

Files here are historical source snapshots. They can contain obsolete absolute
paths, local SDK/device commands, old multi-remote push behavior, incomplete
experiments and former execution-grant conventions. Some run commands on import.
**Do not execute or import them.** Their rescue does not authorize any of those
operations, make them production code or establish that they pass current checks.
All new checks/builds remain GitHub-hosted only. The current root AGENTS policy
and task plan supersede every historical command and success claim here.

## Selection and deduplication

- Preserve unique curriculum authoring helpers and historical Rust variants.
  Skip Rust snippets already present in tracked catalog fields.
- Preserve unique offline-IDE helper source and selected small evidence records.
  Generated reports/catalog snapshots, process grants, logs, binaries and caches
  are not bulk copied. Useful log knowledge is summarized separately.
- For native patchwork, compare both same-relative-path trees and preserve only
  the six changed source pairs, plus a historical delta. Do not copy unchanged
  upstream trees. Preserve the three small filesystem-patch snapshot sets with
  byte-level deduplication and historical deltas; do not apply them to the product.
- Preserve unique unreachable blobs exactly, once per content. Blobs already
  represented by tracked working-tree content are referenced instead of copied.
- Refer to `historical-log-summary.md` for sanitized knowledge from the 33 raw
  release logs. Those logs are historical, not new verification evidence.

Original files and Git objects remain in place. This directory is not permission
to delete originals: provenance, cloud validation and final receiving-clone
comparison remain separate coordinator gates. See `../preservation-rescue.md`
for the review boundary, exact manifests and unresolved items.
